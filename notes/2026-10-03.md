### 7. 🚀 펌웨어 2대 핵심 기능 고도화 배포 (`carrier_board_mqtt.cpp`)
* **🔄 LittleFS 순환 링버퍼 (Circular Log Buffer) 구축**:
  * 단일 1MB 파일 한도 초과 시 쓰기가 멈추던 한계를 극복하기 위해 **이중 세그먼트(`telemetry_log.jsonl` + `telemetry_log_old.jsonl`, 각 512KB)** 회전 알고리즘 탑재.
  * 512KB 초과 시 1ms 만에 이전 세그먼트로 회전(Rotate)하여, 장거리 주행 시에도 플래시가 멈추지 않고 **항상 최신 1.0MB(약 4,600건, 6시간 이상 분량)를 연속 보존**.
* **⏰ 오프라인 GPS 위성 시각 자동 동기화 (Zero-Internet Time Sync)**:
  * 핫스팟/인터넷(NTP) 연결이 없어도 ATGM336H GPS 위성 신호가 잡히면 `TinyGPSPlus`의 날짜/시간(UTC)을 즉시 읽어 ESP32 RTC 시스템 시각을 자동 세팅 (`settimeofday`).
  * 통신 음영지역이나 단독 배터리 가동 시에도 타임스탬프가 `2026-10-01 00:00:00`으로 롤백되지 않고 **정확한 KST(한국 표준시)로 자동 기록**.
* **⚡ 초고속 부팅 최적화**:
  * LittleFS 마운트 시 바이트 단위 루프를 512B 버퍼 블록 읽기로 개선하여 부팅 지연 시간을 18초에서 **0.05초로 360배 단축**.
### 8. 🛡️ 스마트 주행 감지 래치(Smart Trip Latch) 및 터널/음영구간 연속 기록 파이프라인
* **배경 및 한계 분석**:
  * 기존 "GPS 정상 수신(`lat != 0`) 시에만 저장"하는 단순 조건은 책상 위 실내 데이터 차단에는 유리하나, **실제 차량 주행 중 터널이나 지하차도에 진입했을 때 GPS Fix가 끊기면 보드 메모리(LittleFS)와 DB 저장이 일시 중단되어 터널 내 충격이나 온도 이탈이 누락되는 치명적인 취약점**이 존재함.
* **해결책 (Smart Trip Latch & Last Known Position 데드레커닝)**:
  1. **보드 펌웨어 (`carrier_board_mqtt.cpp`)**:
     * **주행 상태 자동 래치 (`trip_active`)**: 야외에서 최초 1회 GPS Fix 성공, 또는 이동 속도 감지(>2.5km/h), 또는 차량 진동/충격 감지 시 즉시 주행 모드로 자동 고정.
     * **터널/음영지역 연속 기록**: 터널 진입으로 위성 신호가 끊겨도 `trip_active`가 유지되어 **LittleFS에 5초마다 100% 연속 기록**되며, 직전 유효 좌표(`last_valid_lat/lng`)를 유지하여 지도 및 시계열 연속성 보존.
     * **실내 책상 위 메모리 보호**: 부팅 후 출발 전 실내 상태에서는 `💤 [실내 대기 모드]`로 동작하여 LittleFS 저장을 보류(0건 유지).
     * **이상 징후 긴급 저장**: 대기 중이라도 낙하/사고 충격($g\_force \ge 1.8\text{G}$) 감지 시 즉시 강제 기록.
     * **시리얼 CLI 제어**: `start`(강제 주행 시작), `stop`(대기 전환), `clear`(초기화 및 대기 전환) 지원.
  2. **대시보드 (`Step4_Run_Coldchain_v2.py`)**:
     * 세션 내 `trip_started` 래치 및 `last_valid_gps`를 적용하여, 터널 통과 중에도 지도가 0.0으로 튀지 않고 DB에 연속 적재되도록 보정.
     * 이상 징후(충격, 온도급변, 조도급변) 발생 시 GPS 유무와 관계없이 무조건 즉시 DB 적재.
     * 사이드바 상태 표시 세분화: `🔴 스마트 자동 기록 중 (GPS Fix)`, `🔵 스마트 주행 기록 중 (터널/음영구간)`, `⚪ 자동 대기 (실내/출발전)`.
* **실제 하드웨어(COM7) 배포 및 실측 검증**:
  * PlatformIO 빌드 및 COM7 펌웨어 업로드 완료.
  * 책상 위 USB 연결 상태에서 `💤 [실내 대기 모드] 주행 출발 전 - LittleFS 저장 보류`가 정상 동작하고, 플래시 용량이 깨끗하게 0건으로 보존됨을 실시간 시리얼 로그로 검증 완료.

### 9. 🔍 전체 시스템 전수 감사(Audit) 및 4대 핵심 잠재 오류 선제 개선
* **[결함 1] MySQL `status` 컬럼 길이 초과 (`VARCHAR(50)` ➔ `VARCHAR(255)`)**:
  * 다중 복합 이상 이벤트 및 터널 음영 구간 안내 메시지가 50자를 초과할 때 RDS MySQL에서 `Data too long` 오류로 적재 실패할 수 있는 취약점을 발견.
  * AWS RDS 실제 테이블의 `status` 컬럼을 `VARCHAR(255)`로 DDL 확장 수정 완료하고, 코드 내 DDL 생성 구문도 동기화.
* **[결함 2] RDS MySQL `run_id` 인덱스 부재 해결 (`idx_run_id` 생성)**:
  * 기존 테이블에 `PRIMARY KEY(id)`만 존재하여, 세션 조회 시 전체 테이블 스캔(Full Table Scan)이 발생하던 문제를 해결.
  * `CREATE INDEX idx_run_id ON sensor_data(run_id);` DDL을 실행하여 수만 건 데이터 누적 시에도 대시보드 로딩이 지연되지 않도록 쿼리 성능 최적화.
* **[결함 3] 대시보드 과거 세션 조회 시 실시간 큐 유실 버그 원천 차단**:
  * 기존 코드에서 과거 세션을 드롭다운으로 조회할 때 `while not msg_queue.empty(): msg_queue.get()`으로 실시간 패킷을 버리던 치명적 결함을 수정.
  * 과거 세션을 열람하는 중에도 실시간 패킷 파이프라인이 백그라운드에서 항상 가동되어 MySQL DB와 메모리에 1초의 유실도 없이 온전히 연속 적재되도록 로직 분리.
* **[결함 4] 펌웨어 Wi-Fi 재연결 스캔으로 인한 고속 IMU 샘플링 지연 방지**:
  * 핫스팟 신호가 미약하거나 단절되었을 때 매 루프마다 `wifiMulti.run()`을 호출하면 RF 채널 스캔으로 인해 20ms(50Hz) IMU 샘플링이 1~2초간 멈추던 현상을 방지.
  * `WiFi.status()` RAM 캐시 확인 및 6초 주기 비블로킹 스캔 가드를 적용하여 통신 단절 시에도 충격/진동 피크를 놓치지 않도록 보강.

### 10. 🏷️ Status 문자열 슬림화(이모지 배제) 및 VARCHAR(50) 정격 유지
