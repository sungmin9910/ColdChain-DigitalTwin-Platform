## 🔍 2. 1차 주행 테스트 문제점 및 원인 규명 (Root Cause Analysis)

### 2.1 대시보드에는 이동 궤적이 보였으나 DB에는 GPS(위경도 0.0)가 없었던 이유
1. **MQTT 브로커(`broker.emqx.io`)의 특성**:
   * MQTT는 실시간 라우팅 프로토콜이며 기본적으로 데이터를 영구 저장하지 않습니다(QoS 0, Non-retained).
2. **Streamlit 대시보드(RAM) vs AWS RDS(MySQL)**:
   * 주행 중 사용자의 스마트폰 브라우저가 Streamlit 대시보드에 연결되어 있어 대시보드 메모리(`data_history` 세션 리스트)에는 실시간 MQTT 패킷이 들어와 궤적이 그려졌습니다.
   * 반면, AWS RDS 인스턴스(`labdb`)는 예약 설정에 의해 야간에 자동으로 `Stopped(일시 중지)` 상태로 전환되어 있었습니다.
   * 대시보드 백그라운드의 `save_to_mysql()` 함수가 RDS 연결 실패(Connection Refused)로 DB 쓰기를 건너뛰었습니다.
3. **실내 복귀 후 상황**:
   * 밤 23:25경 사용자가 RDS를 다시 시작하자마자 DB 쓰기가 재개되었습니다.
   * 그러나 이 시점에는 이미 실내로 복귀한 후였기 때문에 보드의 ATGM336H GPS가 위성 신호를 잡지 못해(`Fix: NO`), `lat: 0.000000, lng: 0.000000` 데이터만 DB에 연속으로 기록되었던 것입니다.

## 🛠️ 3. 펌웨어 개선 내역 (`carrier_board_mqtt.cpp`)

데이터 유실 방지를 위해 **LittleFS 기반 듀얼 로컬 스토리지 아키텍처**를 구현하고 보드에 플래시 완료했습니다.

### 3.1 듀얼 로깅 구조
1. **마스터 블랙박스 (`/telemetry_log.jsonl`)**:
   * Wi-Fi 및 MQTT 연결 상태와 무관하게 5초마다 측정되는 모든 텔레메트리를 ESP32-C6 내부 플래시 메모리에 상시 Append 기록.
   * 1MB 안전 한도 내에서 최소 4,100건 ~ 최대 5,800건(약 5시간 40분 ~ 8시간 분량) 저장 가능.
2. **오프라인 버퍼 (`/offline_buf.jsonl`)**:
   * 터널, 음영지역 등 핫스팟/MQTT 연결이 끊어졌을 때만 미전송 패킷을 별도 큐잉.
   * 네트워크 복구 시 `flushOfflineBuffer()` 함수가 자동 호출되어 순차적으로 브로커에 전송 후 버퍼 파일 자동 초기화.

### 3.2 시리얼 인터랙티브 CLI 명령어 지원 (115200 bps)
PC 연결 시 시리얼 모니터 또는 터미널을 통해 보드 제어 가능:
* `dump` 또는 `read`: LittleFS에 저장된 모든 원본 JSONL 데이터 스트리밍 출력.
* `info` 또는 `stat`: 현재 LittleFS 전체 용량, 사용량, 누적 기록 건수 실시간 출력.
* `clear` 또는 `reset`: 플래시 메모리 로그 및 오프라인 버퍼 파일 완전 삭제 초기화.

> **현재 보드 상태**: `clear` 완료되어 0건(방금 막 생성된 초기 패킷 1건)으로 대기 중입니다.

## 📋 4. 2차 주행 실험 실행 프로토콜 (Checklist)

### 🚗 출발 5분 전
1. **AWS RDS 시작**:
   * AWS 관리 콘솔 $\rightarrow$ RDS $\rightarrow$ `labdb` 선택 $\rightarrow$ **작업** $\rightarrow$ **'시작'** 클릭 (상태가 `사용 가능`이 될 때까지 약 2~3분 소요).
2. **스마트폰 핫스팟 활성화**:
   * 네트워크 이름(SSID): `hani` / 비밀번호: `12345687` (2.4GHz 대역).
3. **Streamlit 대시보드 새 세션 생성**:
   * 스마트폰 웹 브라우저로 Streamlit 대시보드 접속.
   * 사이드바의 **`🚀 새 실험 세션 시작`** 버튼 클릭 (이전 레코드와 분리된 고유 `run_id` 부여).
4. **센서 보드 전원 인가 및 배치**:
   * 보조배터리에 ESP32-C6 C타입 케이블 연결.
   * **차량 앞유리 대시보드 위(하늘이 트인 위치)**에 거치 (GPS 위성 신호 확보 필수).

### 🛣️ 주행 중
* 터널이나 네트워크 음영지역에서도 LittleFS가 모든 주행 데이터를 100% 로컬 백업하므로 통신 단절을 걱정할 필요가 없습니다.

### 🏁 주행 완료 후 (도착 시)
1. **데이터 CSV 백업**:
   * 스마트폰 대시보드 사이드바의 **`📥 이 실험 데이터 CSV 다운로드`** 클릭.
2. **원본 플래시 메모리 덤프 (선택/보존용)**:
   * PC에 보드 연결 후 시리얼 터미널에서 `dump` 입력 시 1초도 유실 없는 JSONL 로컬 파일 확보 가능.
3. **AWS RDS 중지 (비용 절약)**:
   * AWS 콘솔에서 `labdb` 선택 후 **작업** $\rightarrow$ **'일시적으로 중지'**.
