## 2. 🛠️ 발생했던 핵심 문제점 및 원인 분석

### 2.1 스캔 시 지속적으로 A10으로만 기록되던 버그
* **원인**: ESP32의 `MySQL_MariaDB_Generic` 라이브러리는 `query_executor.execute()` 이후 **반드시 `query_executor.get_columns()`를 먼저 호출**해야 컬럼 메타데이터 버퍼를 초기화하고 `get_next_row()`를 통해 실제 값을 읽어옵니다. 이 호출이 누락되어 직전 이력(`lastLo`)이 항상 `NULL` / `"NONE"`으로 인식되어 기본값인 `A10`으로만 진입했습니다.
* **해결**: `main.cpp`의 DB 조회 루틴에 `get_columns()` 및 `close()`를 추가하고, `lab225.qr` 테이블에 고유 식별 및 명확한 최신순 정렬을 위한 `id INT AUTO_INCREMENT PRIMARY KEY FIRST`를 추가하였습니다.

### 2.2 하드웨어 업로드 모드 진입 불가 및 플래시 중단
* **원인 1**: 3D 프린터 하우징 손잡이의 외부 트리거 스위치는 **GPIO 25**에 연결되어 있었습니다. ESP32의 롬 부트로더 핀은 **GPIO 0(BOOT)**이므로, 외부 스위치를 누른 상태에서는 펌웨어 다운로드 모드(`0x3`)로 진입할 수 없었습니다.
* **원인 2**: 이전의 불완전한 업로드로 인해 ESP32 플래시 메모리가 손상되어 고속 재부팅 루프(`rst:0x3 SW_RESET`)에 빠져 있었습니다.
* **해결**:
  1. 하우징을 개방하여 ESP32 기판 위의 온보드 **[BOOT] 누른 채로 [EN] 1회 클릭**을 통해 하드웨어 롬 다운로드 모드(`boot:0x3 (DOWNLOAD_BOOT)`)로 직접 진입.
  2. 플래시 메모리 전체를 완전히 비우는 **Chip Erase**를 선행한 후 115,200 baud 클린 플래싱을 수행하여 100% 완벽 업로드 달성.

### 2.3 A12 선별 프로그램의 중복 키 충돌 에러 (`Duplicate entry '32' for key 'qr.PRIMARY'`)
* **원인**: [Step3_Sorting_QR_Creator.py](file:///c:/Users/korea/Desktop/1hsm/hanhanhan/ColdChain-DigitalTwin-Platform/Final_Experiment/1_PC_QR_Generators/Step3_Sorting_QR_Creator.py)가 A11 레코드를 `SELECT *`로 읽어와 새 A12 레코드를 삽입할 때, 이전 A11 레코드의 `id`(32)까지 그대로 `INSERT` 대상 컬럼에 포함하여 Primary Key 충돌이 발생했습니다.
* **해결**: `data_to_insert = {k: v for k, v in data_dict.items() if k in db_columns and k != 'id'}`로 수정하여, 신규 레코드는 항상 MySQL이 새 고유 번호를 자동 발급(`AUTO_INCREMENT`)하도록 조치하였습니다.

## 4. 🔌 하드웨어 분리 및 차후 운용 안내

1. **보드 분리 가능 여부**: **즉시 USB 케이블을 분리하셔도 안전합니다.**
   - 업로드된 펌웨어는 ESP32의 비휘발성 플래시 메모리(Non-volatile Flash ROM)에 영구 기록되어 있으므로 전원이 꺼져도 지워지지 않습니다.
   - 3D 하우징을 재조립하신 뒤 배터리나 외장 보조배터리 전원을 인가하면 언제든지 자동으로 Wi-Fi(`hani`)에 접속하여 `[ AUTO ]` 모드로 즉시 동작합니다.
2. **백그라운드 프로세스 정리**:
   - 시리얼 포트를 감시하던 로거(`live_scanner_logger.py`), GUI 선별창, 대시보드 프로세스를 모두 정상 종료하여 컴퓨터 리소스 및 COM 포트 점유를 완전히 해제하였습니다.
